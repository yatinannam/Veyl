# Decision log

Lightweight ADRs. Status is `accepted` unless noted. Details live in the [design spec](superpowers/specs/2026-10-15-veyl-design.md).

| ID | Date | Decision | Alternatives considered | Why |
|---|---|---|---|---|
| D-001 | 2026-10-15 | **Everything must be $0 with no credit/debit card.** | Paid APIs (Claude, OpenAI) | Hard user constraint. Drives D-002, D-003, D-009. |
| D-002 | 2026-10-15 | LLM via one **OpenAI-compatible client**; default **Groq free tier**; Gemini AI Studio / Ollama / OpenRouter `:free` as config-only alternatives | Claude API (paid), OpenAI (paid), Ollama-only (heavy on laptop) | Free without card; provider swap is just env vars. |
| D-003 | 2026-10-15 | Embeddings: **`BAAI/bge-small-en-v1.5` (384-dim) via fastembed**, run locally | Voyage/OpenAI embeddings (paid), sentence-transformers + PyTorch (huge image) | Free, offline, small ONNX runtime. |
| D-004 | 2026-10-15 | Auth: **opaque session token in httpOnly cookie, hashed in Postgres**, argon2id passwords, CSRF double-submit | Stateless JWT, external IdP | Instant revocation; role re-read every request; fail-closed friendly. |
| D-005 | 2026-10-15 | Ingestion: **separate worker + Postgres job table** (`FOR UPDATE SKIP LOCKED`) | FastAPI BackgroundTasks, Redis + Celery | Durable async jobs without extra infrastructure. |
| D-006 | 2026-10-15 | Retrieval authz: **ACL denormalised onto chunks, filtered inside the vector query, re-checked in Python**; tenant isolation also enforced by **Postgres RLS** | Join to source-of-truth ACL per query; store-per-tenant | Matches brief's chunk-metadata requirement, fast, defense in depth. |
| D-007 | 2026-10-15 | Stale-permission defense: `acl_version` on documents + chunks, must match at query time; tenant `policy_version` in cache keys | Rely only on transactional rewrite | Stale chunks become invisible even if a rewrite were missed. |
| D-008 | 2026-10-15 | Retrieval cache stores **chunk IDs only**; content re-fetched through the authz filter on hit | Caching answers / chunk text | Cache structurally cannot leak content. |
| D-009 | 2026-10-15 | Hosting: **local Docker Compose only** for now | Free cloud hosts | Worker + embedding model RAM is tight on free hosts; revisit after the app works. |
| D-010 | 2026-10-15 | Backend data access: **SQLAlchemy 2.0 sync + psycopg 3**; tests on real Postgres via **testcontainers** | Async SQLAlchemy/asyncpg; mocked DB | Simpler transaction/RLS handling; RLS needs a real DB to test. |
| D-011 | 2026-10-15 | Only the one-shot `migrate` service gets DB-owner credentials; api/worker use `veyl_app` (no BYPASSRLS) | API runs migrations on boot | Least privilege — a compromised API can't disable RLS. |
| D-012 | 2026-10-15 | Phase 0 ships **without the worker service**; it arrives in Phase 3 with real job handling. `TEST_DATABASE_URL` override deferred — tests always use testcontainers. | Idle placeholder worker container | Avoid placeholder services; CI runners have Docker. |
| D-013 | 2026-10-15 | Frontend on **Next.js 16.4** with create-next-app defaults kept (React Compiler, `cacheComponents`); type-check runs `next typegen` first | Strip framework defaults | Generated, tested defaults; route types are generated, so a clean checkout needs typegen. |
| D-014 | 2026-10-16 | **No emojis anywhere in the project** (docs, code, UI, commits); enforced by a repo-wide unit test | Convention only | User rule; a test keeps it true. |
| D-015 | 2026-10-16 | RLS predicates use `app_current_tenant()` (`NULLIF(current_setting(...), '')::uuid`); each table has a `*_tenant_isolation` policy for `veyl_app` and a `*_owner_all` policy for `veyl_owner` | Bare `current_setting(...)::uuid`; not forcing RLS on the owner | A used transaction-local setting reads back as `''`, which would raise instead of matching nothing; SECURITY DEFINER lookups run as the owner and need cross-tenant reads while FORCE RLS stays on. |
| D-016 | 2026-10-16 | Data access via **SQLAlchemy Core**; migrations are **hand-written SQL** | ORM + autogenerate | RLS, policies, grants, and definer functions are SQL anyway; a test asserts the Core tables match the migrated schema. |
| D-017 | 2026-10-16 | `POST /auth/login` is **exempt from the CSRF token** | Pre-login CSRF token endpoint | No CSRF cookie exists before login; JSON-only body, no CORS, and SameSite=Lax cookies block cross-site submission. |
| D-018 | 2026-10-16 | Tenants are created by an **operator CLI with owner credentials**; no tenant-creation API | Admin API for tenant signup | Keeps `veyl_app` unable to insert tenants; self-service signup is out of scope. |
| D-019 | 2026-10-16 | Auth audit events (`auth.login_*`) are deferred to **Phase 4** | Ad-hoc auth log table now | The audit table and its immutability guarantees are designed in Phase 4. |
| D-020 | 2026-10-16 | **Superseded by D-022.** uvicorn trusts `X-Forwarded-For` behind the local Next.js proxy | Rate-limit by proxy IP only | The original reasoning (safe because the API port is localhost-only) was wrong: the forged header arrives through the public proxy. |
| D-021 | 2026-10-16 | Login rate-limiter keys are dropped once they have no failures in the window | Retain a key per probe | Prevents unbounded memory growth under account enumeration. |
| D-022 | 2026-10-16 | Add **`edge` (Caddy) as the only public entry point**; it overwrites `X-Forwarded-For` with the real peer address. `web` is no longer published. | Next.js middleware (cannot see the socket address in Next 16); drop per-IP limiting (loses password-spray protection) | Next.js forwards a client-forged `X-Forwarded-For` unchanged (it only sets the header when missing); a trusted edge makes the API's client IP authoritative. Found by the Phase 2 review; proven by `docker/smoke/login-ip-limit.sh` (failed before, passes after). |
| D-023 | 2026-10-16 | **Cap concurrent password verifications** (default 4, 2 s wait, then 429) | Unbounded argon2 work per request | Bounds memory and worker-thread use under a login flood, whatever identity the attacker presents. |
| D-024 | 2026-10-16 | `allowed_roles` is `text[]` with a CHECK (`<@ ARRAY['member','manager','admin']`) instead of `user_role[]` | Enum array | Same rejection of unknown roles, without enum-array adapter fragility in psycopg/SQLAlchemy. |
| D-025 | 2026-10-16 | No query endpoint in Phase 3; retrieval is a service tested directly | Temporary search endpoint | `POST /query` arrives with the LLM in Phase 4; avoids an extra API surface. |
| D-026 | 2026-10-16 | The embedding model is baked into the backend image (`/opt/models`, `HF_HUB_OFFLINE=1`) | Download at container start | No runtime network dependency; reproducible, offline, $0. |
| D-027 | 2026-10-16 | The worker splits `prepare` (extract, chunk, embed; no long transaction) from `persist` (FOR SHARE on the document, copy the current ACL) | One long transaction | Short locks; a permission change during ingestion always reaches the new chunks, and the `acl_version` guard hides anything stale. |
| D-028 | 2026-10-16 | Retrieval sets `hnsw.iterative_scan = relaxed_order` and sorts by score in Python; recall under heavy ACL filtering in large tenants is documented as best-effort | Exact search only; partitioned indexes | EXPLAIN shows small tenants are pre-filtered through the tenant btree (exact). HNSW is approximate, so a deterministic recall guarantee is not possible; authorization never depends on it. |
| D-029 | 2026-10-16 | Membership changes lock the tenant row `FOR NO KEY UPDATE` | `FOR UPDATE` | Does not conflict with foreign-key KEY SHARE locks, so document and chunk inserts are never blocked (Phase 2 review). |
| D-030 | 2026-10-16 | Text extraction runs in a **spawned child process** with a wall-clock limit (`EXTRACTION_TIMEOUT_SECONDS`, 60), an address-space limit on Linux (`EXTRACTION_MEMORY_MB`, 1024), and an extracted-text cap (`MAX_EXTRACTED_CHARS`, 2,000,000) | In-process extraction | pypdf's extraction time is quadratic in page content size: a 6 KB PDF took 7.9 s, a 20 KB one minutes. One upload could stall ingestion for every tenant (Phase 3 review). |
| D-031 | 2026-10-16 | `ingestion_claim_job` takes `p_max_attempts`; stale running jobs that used every attempt are failed with their document instead of reclaimed (migration 0004) | Reclaim forever | A file that crashes or hangs the worker process never reaches the Python failure path; without a cap it returns every 10 minutes indefinitely. |
| D-032 | 2026-10-16 | A document becoming `ready` bumps the tenant `policy_version` | Separate content version | Cached results computed before the document existed would otherwise hide it for the cache TTL. One version keeps the cache key simple. |
| D-033 | 2026-10-16 | Default LLM **`openai/gpt-oss-120b` on Groq**; only `message.content` is used | `llama-3.3-70b-versatile` (no longer offered to the account) | Verified against the account's model list; answered with a correct citation in 0.6 s. Provider `reasoning` output is never surfaced. |
| D-034 | 2026-10-16 | `RETRIEVAL_MIN_SCORE` default **0.5** | 0.0 (always send something to the model) | Measured on bge-small: relevant top scores 0.60-0.78, unrelated questions at most 0.45. Below the threshold the model is not called at all. |
| D-035 | 2026-10-16 | LLM client uses **urllib** from the standard library | httpx/openai SDK | No new dependency for one POST; tested against a real local HTTP server. |
| D-036 | 2026-10-16 | Conversation **views** also hide answers whose cited chunks the user can no longer read | Re-authorize only the prompt history | Re-displaying an old answer would keep leaking content after access is revoked. |
| D-037 | 2026-10-16 | CI and offline demos use **`docker-compose.stub.yml`**, a stdlib LLM stand-in that answers from source S1 | Real key in CI secrets | CI stays $0 and key-free while still exercising retrieval, prompt, citations, and audit end to end. |
| D-038 | 2026-10-16 | The audit table's append-only **trigger binds the owner** too (UPDATE/DELETE/TRUNCATE raise) | Grants only | Grants already stop the app role; the trigger also stops migrations or a mistaken owner session from rewriting history (a superuser can still disable triggers: spec section 11). |
| D-039 | 2026-10-16 | Messages are stamped with **`clock_timestamp()`** | Transaction `now()` | Both messages of an exchange share one transaction; `now()` made them tie and history replayed in random order. |
| D-040 | 2026-10-16 | Assistant messages store **`source_chunk_ids`** (every chunk given to the model); an answer is visible and replayed only while all of them and all cited chunks are readable (migration 0006) | Re-check cited chunks only (spec's original wording) | A model can use a source without citing it; checking citations alone let such answers survive revocation (Phase 4 review). |
| D-041 | 2026-10-16 | The LLM client **refuses HTTP redirects** | urllib default (follow) | urllib follows a redirect with the `Authorization` header, sending the API key to the new host (reproduced in review). |
| D-042 | 2026-10-16 | Citation labels are **renumbered S1..Sm in order of first appearance**, and conversation views return the same citation list | Keep the model's labels | Stored answers must map each `[S#]` to a stored chunk so the chat can show citations when a conversation is reopened. |
| D-043 | 2026-10-17 | New **`user.directory`** action (managers and admins): `GET /users/directory` returns active colleagues' id, email, role | Reuse admin-only `GET /users`; type user ids by hand | Uploaders need to pick people to share with; the directory exposes only what sharing needs, never inactive users or timestamps. |
| D-044 | 2026-10-17 | Citations carry the chunk's **classification** | Look up each document from the client | The source card shows the level next to every citation without extra requests or a second permission check. |
| D-045 | 2026-10-17 | Dashboard fetches **client-side through the same-origin `/api/v1` proxy**; `proxy.ts` only checks that the session cookie exists; native form controls | Server components calling the API with forwarded cookies; component library for forms | One path for every request keeps the CSRF and cookie model unchanged; the API stays the only authority (a present-but-stale cookie is caught by the session provider's 401 redirect). Native controls are accessible by default and add no dependencies. |
| D-046 | 2026-10-17 | Visual identity: **classification bands** (public sage, internal blue, confidential amber, restricted oxblood) on a light, quiet interface; IBM Plex Sans for the interface, Source Serif 4 for answers | Dark "security console" theme | The levels are what users must notice; one colour per level, always beside its name, so colour is never the only signal. Answers in a serif read as excerpts of documents. |
| D-047 | 2026-10-17 | Answers render a **small Markdown subset** (paragraphs, bullet and numbered lists, bold, headings as paragraphs) as React text; never HTML | Raw text; a full Markdown library | The model answers in light Markdown and raw `**` looked broken (seen in screenshot review); a full renderer would add a dependency and an HTML-injection surface for model output. |
